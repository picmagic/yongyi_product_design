# 部署与更新说明

## 仓库与本地目录

- GitHub 仓库：<https://github.com/picmagic/yongyi_product_design>
- 本地目录：`/Users/Admin/workspace/用一科技/prototype`
- 日常修改分支：`dev`
- 正式发布分支：`main`，由开发同事创建、审核并合并

原型文件直接位于仓库根目录。此仓库保存的是 Axure 原始 HTML 导出文件，不需要发布助手、Node.js、npm、数据库或后端进程。Axure 生成的脚本和样式需要随原型一起保留。

## 首次部署

1. 在 Vercel 导入此 GitHub 仓库。
2. Root Directory 选择仓库根目录，Framework Preset 选择 `Other`。
3. 打开 Build Command 的 Override，将命令留空；Output Directory 设为 `.`。
4. 选择要部署的分支。正式使用时，在项目 Git 设置中将 Production Branch 设为 `main`。如果仓库还只有 `dev`，先由开发同事将验收后的版本创建为 `main`。
5. 部署完成后打开项目域名，确认首页、左侧页面目录、中文页面名、图片和跨页交互可用。

不需要另行编译或安装依赖。保留各文件路径，不要把所有请求重写为 `index.html`。域名和访问权限由部署方在 Vercel 中管理。

如果改用公司服务器，静态站点根目录指向本仓库即可，默认首页设置为 `index.html`，完整复制全部 HTML 和配套资源。

## 每次更新

1. 更新前确认处于 `dev`，检查当前工作区并同步远端。存在未提交文件时，先保存当前工作；不要通过重置覆盖本地改动。
2. 在 Axure 重新导出整个原型。将新导出内容同步到本目录，同时保留 Git 和维护文档。
3. 对照本次导出，移除已失效的旧页面及其资源；不要删除新导出中仍使用的文件。不要清空或替换 `.git/`，也不要覆盖 `README.md`、`.gitignore` 和 `docs/`。
4. 查看 Git 的新增、修改和删除文件，确认它们符合本次设计变更。使用本地 HTTP 预览或 Vercel 的 `dev` 预览部署，检查改动。
5. 确认后提交并推送：

```sh
cd '/Users/Admin/workspace/用一科技/prototype'
git status
git add --all
git diff --cached --stat
git commit -m 'docs(prototype): update Axure export'
git push origin dev
```

6. 由开发同事将 `dev` 合并到 `main`；绑定 `main` 的 Vercel 项目会自动部署新版本。使用同一个项目域名时，对外分享的地址可以继续使用。

`dev` 的预览版本与 `main` 的正式版本可能不同。没有修改需要提交时，跳过 commit 和 push。

## 交付范围

本次同步保留 Axure 导出文件的原始内容和目录关系，只额外提供 Git 忽略规则与维护文档。macOS 的 `.DS_Store` 等缓存文件不进入版本管理。

页面目录和原型交互由 Axure 导出文件提供。在线上传、服务器写入和多人共享评论没有包含在这套静态原型中。
